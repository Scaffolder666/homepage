Externalization

2
CHI 2026 · 2D/3D software workPointAloudExternalization

原论文：交互流程

  1. 用户在 2D / 3D 软件任务中边工作边 verbalize，系统同时记录 pointer location 与上下文。
  2. TalkPointer 提供低干扰反馈并把 verbalization 形成 contextually anchored TalkNotes。
  3. TalkExplorer 让用户按主题回看这些 captured moments，系统也可在工作过程中给出短促的 proactive suggestions。

交互机制：pointer-anchored think-aloud + contextual retrieval，把 fleeting reasoning 变成之后可重新进入工作流的知识。

Cognitive mechanism · working mapping: Externalization + retrieval.

CAD 迁移（设想）：将“这个角度我只是凭经验”“之后还要检查这个连接”一类 verbalization 自动绑定到几何与操作历史，在相关 feature 再次出现时重新 surface。

边界：think-aloud 只能捕捉被 verbalize 的内容，并不等于完整读取 tacit knowledge。

原论文：交互流程

  1. 参与者围绕 tangible privacy management 的设计任务，使用有组织的实体创意卡片。

边界：卡片推动构思，不负责提供足以支持技术决策的验证资料。

Decomposition

3
CHI 2024 · 平面设计CreativeConnectDecomposition

原论文：交互流程

  1. 设计师导入用来启发构思的参考图片；系统把参考拆解为可以操作的概念词。
  2. 设计师浏览相关概念和关联词，选择要保留、组合或进一步探索的概念。
  3. 系统把选定概念重组为可视化草图方向，设计师再据此调整构思。

交互机制：把不可直接编辑的“整张参考图”转成多个可分开选择的语义维度，再从组合反馈中发现之前未考虑的方向。

Cognitive mechanism · working mapping: Decomposition + analogy.

CAD 迁移（设想）：将一个参考产品拆成支撑、移动、安装、材料等维度，让设计师选择某个维度后发现模型中尚未显式考虑的选择。

边界：这是参考重组和创意探索工具。制造可行性与 decision grounds 需要额外证据。

CHI 2025 · UI 原型MistyDecomposition

原论文：交互流程

  1. 开发者导入自己的在制 UI 代码，以及参考 UI 的截图或手绘草图；早期也可用整屏的 global blending 探索总体方向。
  2. 需要精细控制时，从参考界面选取局部区域，把它拖放到当前界面对应组件，并指定只混合 Color、Layout、Content 等某个属性。
  3. 系统生成新的 UI 代码与预览，同时把修改整理成按语义分类的 diff，例如“改为深色主题”“改变卡片布局”。
  4. 开发者逐项开启、关闭或细调这些修改，也可以直接编辑代码；保留新布局的同时恢复原来的颜色。

交互机制：先分解“借鉴参考设计”的含糊意图，再用语义级开关进行可逆的局部融合。重点是选择混合哪一种属性。

Cognitive mechanism · working mapping: Decomposition + comparison.

CAD 迁移（设想）：把“借用其他产品的方案”细化为只借结构、连接方式或材料等选择；对每类几何变化提供可单独撤销的语义 diff。

边界：论文主要涉及静态 UI 的视觉与内容混合；用户发现新的设计维度是可能的交互启发，不等于论文验证了决策意识的改变。

边界：如果发现问题时还缺测试，实际应归入左下；已有数据也不一定足以支持工程判断。

Elicitation

2
CHI 2026 · UI/UX designClearFairyElicitation

原论文：交互流程

  1. 系统把设计过程组织成可追踪的 decision steps，并判断解释是否 strong、weak 或 empty。
  2. 当 rationale 不完整时，在相关 Figma 元素上直接提出轻量 clarifying question，同时降低持续 think-aloud 的负担。
  3. 系统根据过去的解释与行动推断缺失 rationale，再让设计师接受、修正或继续补充。

交互机制：in-situ elicitation + rationale inference，把本来隐性的“为什么这么做”转成可检查、可复用的 decision knowledge。

Cognitive mechanism · working mapping: Elicitation + self-explanation.

CAD 迁移（设想）：当一个 CAD feature 被创建或修改但理由不清楚时，在对应 geometry 上轻量询问约束、目标或 trade-off，并把回答绑定到该 decision。

边界：推断的 rationale 需要设计师确认、修改或拒绝。它适合 unarticulated rationale；外部工程证据需要独立来源。

CHI 2025 · human–GenAI co-creationIntentTaggerElicitation

原论文：交互流程

  1. 在 slide creation 中，用户把当前想表达的 intent 写成小粒度的 Intent Tags，每个 tag 对应一个可单独操作的 conceptual unit。
  2. 用户可以在不同 ambiguity level 下创建、组合、修改和移除 tags，让 meta-intent 和局部要求逐步显式。
  3. AI 依据这些 tags 生成或修改内容；用户继续调整 tags，并用相同 intent 组织后续 co-creation workflow。

交互机制：granular intent reification + micro-prompting，把含糊意图拆成可编辑、可组合、可持续修正的对象。

Cognitive mechanism · working mapping: Elicitation + constraint articulation.

CAD 迁移（设想）：把“保持手臂活动空间”“这里还需要 PT review”“希望使用单一材料”等 intent 做成 geometry-linked tags；随着模型发展逐步补充、合并或具体化为 constraint。

边界：Intent Tags 表达用户 intent。材料限制、人体参数和工程要求仍需要对应的数据、标准或专家输入。

Retrieval

4
CHI 2026 · 3D scene editingGroundLinkRetrieval

原论文：交互流程

  1. 从既有会议记录中捕捉 decisions、comments、constraints 与 creative intent。
  2. 在 Unity 3D editor 中把 meeting snippets 与具体 scene objects 建立双向链接。
  3. 当用户编辑相关对象时，constraint-aware feedforward 主动提示过去的决策或潜在冲突。

交互机制：contextual resurfacing + cross-modal linking，把团队已经拥有但当前没有在场的知识重新带回工作情境。

CAD 迁移（设想）：选择或修改一个部件时，自动调出此前与它相关的讨论、实验结果、专家评论或 unresolved constraint。

边界：这最接近 dormant prior knowledge 与 team-level tacit knowledge；被 resurfaced 的旧信息仍可能过时或不再适用。

CHI 2025 · narrative creativity supportClueCartRetrieval

原论文：交互流程

  1. 用户把散落在 game world 中的 narrative clues 收集到系统中，并按 hierarchical clue taxonomy 组织。

CHI 2025 · multimodal memoryOmniQueryRetrieval

原论文：交互流程

  1. 系统从 photos、screenshots 和 videos 中保存 captured memories，并识别散落在多个 memories 之间的 contextual information。
  2. 用户提出需要跨多个 memories 才能回答的问题；系统先把相关 memories 做 contextual augmentation。
  3. 系统检索这些 augmented memories，并生成带 reference memories 的回答，让用户可以回看来源。

交互机制：contextual augmentation + referenced retrieval，把分散在多个 records 中的 context 组合后再用于当前 query。

Cognitive mechanism · working mapping: Retrieval + contextual augmentation.

CAD 迁移（设想）：给 design photos、fabrication videos、meeting screenshots 和 field observations 增加 project / component / decision context；编辑相关 geometry 时检索跨 modality 的 prior evidence。

边界：personal memory QA 的 context inference 可能出错。CAD 中需要显示 source、time、component link 和用户确认状态。

3

原论文：交互流程

  1. BLV programmers 在 OpenSCAD 中通过 source code 创建和修改 3D model。

边界：A11yShape 验证的是 BLV programmers 的 accessible 3D modeling。这里把它映射到 representation-bound knowledge，用于思考 representation 如何决定 knowledge 能否进入当前 decision。

Analogy

1
UIST 2021 · 图形符号SymbolFinderAnalogy

原论文：交互流程

  1. 设计师先给出需要表达的抽象概念，再沿语义关联探索具体图标表达。
  2. 系统围绕这个概念组织局部语义关联，设计师沿着关联查看不同具体意象与符号方向。
  3. 设计师比较不同关联所能传达的意义，再选择值得继续发展的视觉表达。

交互机制：通过“抽象概念 → 局部语义联想 → 具体视觉象征”的可探索路径，扩大设计师最初没有想到的表达空间。

Cognitive mechanism · working mapping: Analogy / associative reasoning.

CAD 迁移（设想）：选中一个部件，展开与它相关但当前未考虑的功能、使用场景或连接关系；用户点击其中一个方向，才生成新的待决事项。

边界：提出关联并不意味着相关工程标准或证据已经充分，只有问题未被意识到而依据可取得时才映射到本象限。

Reframing

2
IUI 2023 · 人机共绘ReframerReframing

原论文：交互流程

  1. 人和 AI 在同一个绘图过程中同步创作，用户持续画、观察系统产生的变化，再修改自己的草图。
  2. 作者比较两种交互风格：一类让系统表现出较强的自主涌现性，另一类强调用户的直接控制。
  3. 用户在不断出现的图形反馈与自身绘制之间往返，而非提交提示后只接收一张完整图片。

交互机制：实时的意外变化可以触发重新解释；不同控制程度也会改变用户如何接续自己的创作。

Cognitive mechanism · working mapping: Reframing.

CAD 迁移（设想）：当用户粗略修改形体时展示可控的局部发展方向，借意外形态让他意识到一个未明确的设计选择。

边界：涌现不保证有用，也不代表生成形状具有工程依据；论文没有验证这里的四象限分类。

UIST 2025 · academic communicationPaperBridgeReframing

原论文：交互流程

  1. 研究者导入自己的 publications，并先从 communication goal 或想讲的主题出发提出 top-down organization intent。

边界：PaperBridge 研究 academic narrative。CAD reframing 需要定义能够反映真实 design relations 的 grouping semantics。

Reflection

1
CHI 2023 · design educationKaleidoscopeReflection

原论文：交互流程

  1. 学生持续把 sketches、prototype photos、Figma layouts、notes 等设计过程 artifacts 放入 Studio Space。
  2. 项目历史保持可见，并把 feedback 与具体 artifact 及更大的 design context 放在一起。
  3. 用户回看过去的 artifacts 与反馈，对自己的过程进行显式 reflection。
